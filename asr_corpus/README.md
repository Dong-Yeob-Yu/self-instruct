# 로컬 발화 데이터 스튜디오

## 유형과 비율을 지정하는 숫자 생성

웹에서 금액·금리·온도·날짜·시간·전화번호·소수·수량·순서·비율을 선택하고 상대 비율을 입력합니다.
예를 들어 금액 3, 수량 1이면 전체 목표를 약 3:1로 배분합니다. 정수 개수의 나머지는 최대 나머지 방식으로
배분하고 동률이면 표시 순서를 따릅니다. 목표가 선택 유형 수보다 작으면 일부 유형은 0개가 됩니다.

코드가 유형과 비율에 맞는 아라비아 숫자를 먼저 생성하고, LLM이 `{number}`를 포함한 템플릿과 유형별 한글 읽기를 두 단계로 생성합니다.
이 값을 `type`, `context`, `unit`과 함께 LLM에 전달해 한글 읽기를 받은 뒤, 같은 템플릿에 발화와 정답을 각각 매핑합니다.
금액을 체크하면 **금액 자릿수 비율** 설정이 나타납니다. 1~9자리별 상대 비율을 입력하며 기본값은 모두 1입니다.
0인 자릿수는 생성하지 않습니다. 예를 들어 2자리 1, 9자리 3이면 금액 채택 목표를 약 1:3으로 배분합니다.
유형별 금액 목표를 먼저 정한 뒤 자릿수별 목표를 최대 나머지 방식으로 배분하며, 실패한 항목은 미달 자릿수에서 재시도합니다.
목표가 선택한 자릿수 수보다 작으면 일부 자릿수는 0개입니다. 나머지가 같으면 작은 자릿수부터 배분합니다.
선택한 자릿수 범위 안에서 정수를 원 단위로 균등 추출합니다. 천 원·만 원 단위로 반올림하지 않으며 중간의 0도 보존합니다.
작은 자릿수는 가능한 값이 적으므로 같은 금액도 문장이 다르면 사용할 수 있습니다. 완전히 같은 발화·정답은 제외합니다.
모든 유형의 숫자 난수에는 작업 ID와 배치 시드를 함께 사용해 새 작업에서 동일 숫자 배열을 반복하지 않습니다.
유형별 범위와 형식은 유지합니다. 예를 들어 전화번호는 010 접두어, 소수는 소수점 아래 두 자리입니다.
금액 뒤의 이/가·은/는·을/를·과/와·으로/로는 단위 원의 받침에 맞춰 자동 보정합니다.
`이(가)` 같은 선택형도 하나로 확정하고 발화·정답에 동일하게 붙입니다. 예: `오십삼 원이 부족합니다.` ↔ `53원이 부족합니다.`
금액 유형은 값이 다르면 같은 문장 틀도 채택합니다. 정확히 같은 발화·정답의 중복, 정답 충돌, 숫자 읽기 오류는 계속 검사합니다.
온도 발화는 ℃를 자연스러운 일상 표현인 ‘도’로 읽으며 정답의 ℃ 표기는 유지합니다. 기존 저장 음성은 자동 수정하지 않습니다.
시간은 시각과 소요 시간, 순서는 순번과 등수를 구분합니다. 금리와 비율도 별도 유형으로 관리합니다.
한글 읽기는 유형별 기준과 값의 일치를 검사하며 잘못된 읽기는 검토 대상으로 남기고 부족한 유형을 재시도합니다.
코드가 만든 값과 유형·문맥·템플릿은 작업과 텍스트 JSONL 내보내기에 보존합니다.

텍스트 검토 화면의 ‘숫자가 문장이 되는 과정’에서 현재 생성 단계와 유형별 채택/목표 개수를 볼 수 있습니다.
코드 생성 숫자를 먼저 표시하고, LLM 템플릿과 한글 읽기가 돌아오면 최종 매핑을 이어서 표시합니다.
배치별 기록은 최신순으로 펼쳐볼 수 있고 오류·중지 시점의 중간 결과도 남깁니다. 접기 상태는 자동 조회 중에도 유지합니다.
기존 작업에 단계 기록이 없으면 저장된 템플릿·숫자·발화로 가능한 범위의 결과를 표시합니다.
UI는 차콜 배경과 청보라색 강조의 다크 테마를 사용합니다.

웹 UI는 텍스트를 먼저 생성한 뒤 목록에서 체크한 한글 발화만 TTS에 전달합니다.
API의 `auto_audio: true` 요청은 기존 전체 자동 생성 흐름을 유지합니다.
LLM 추론 프로세스가 종료된 뒤에 TTS 실행 잠금에 진입하며, 정답지의 아라비아 숫자 문장은 TTS에 전달하지 않습니다.
MLX TTS는 BF16 본체를 한 번 로딩해 전체 발화의 음성 코드를 만든 뒤 본체 워커를 종료합니다.
그 다음 BF16 코덱만 로딩해 전체 코드를 WAV로 변환하고 코덱 워커도 종료합니다.
본체와 코덱을 동시에 로딩하지 않으며 완료·취소·오류 모두 해당 워커 종료를 기다립니다.
모델 다운로드는 추론 시 자동으로 실행하지 않으며 모델과 코덱을 로컬에 미리 준비해야 합니다.
MLX 백엔드는 `--tts-backend mlx --tts-model-dir <모델 경로> --tts-codec-dir <코덱 경로> --tts-python <MLX Python 경로>`로 선택합니다.
웹에서는 목록 체크로 음성 생성·저장 대상을 고릅니다. 하단 저장은 체크한 항목 중 WAV가 준비된 것만 포함합니다.

API에서는 `type_weights`에 `money`, `interest_rate`, `temperature`, `date`, `time`, `phone`,
`decimal`, `count`, `ordinal`, `ratio`를 키로, 1~10,000의 정수 가중치를 값으로 전달합니다.
`money_digit_weights`에는 `{"2": 1, "9": 3}`처럼 자릿수 문자열과 0~10,000 정수 비율을 전달합니다.
금액 유형에서 생략하면 1~9자리 균등 비율을 사용합니다. 설정은 작업 기록과 브라우저 초안에 보존합니다.
`type_weights`를 생략한 API 요청과 기존 작업은 이전 생성 방식을 유지합니다.
아래의 parts·공통 읽기 설명은 이 호환 모드에 적용됩니다.

프롬프트로 주제와 표기 규칙을 정하고 한 화면에서 **설정 → 발화 검토 → 음성 검토·저장** 작업을 진행합니다.
기본 TTS는 MOSS-TTS 8B BF16 + BF16 MOSS 코덱을 사용하는 MLX 백엔드이며, 기존 Magpie F16도 선택할 수 있습니다.
 학습 자료 형식은 Qwen ASR 프로젝트를 사용합니다.

## 실행

프로젝트 루트에서 기존 실행 옵션을 유지해 앱을 재시작합니다.

```bash
python3 -m asr_corpus.web
```

기존에 사용한 `--model-file`·`--llama-executable` 옵션이 있으면 함께 지정합니다.
개발·운영 서버의 실행과 재시작은 사용자가 직접 합니다.

## 한 화면에서 작업하기

데스크톱은 왼쪽 생성 설정과 오른쪽 발화 목록을 동시에 표시합니다.
별도 헤더·항목 상세 없이 생성·수정·음성 재생·저장을 진행합니다.

- **발화 생성**은 텍스트만 만듭니다. 목록에서 체크한 뒤 **선택한 N개 음성 생성**을 누르거나 행의 **음성 생성**을 누릅니다.
- 생성된 행에 재생·일시 정지 버튼과 실제 PCM16 WAV에서 계산한 파형이 나타납니다. 파형 클릭 또는 방향키·Home·End로 탐색합니다.
- 발화·정답은 항상 표시된 입력창에서 바로 편집합니다. **저장/취소**, **Ctrl·⌘+Enter/Esc**로 마칩니다. 자동 조회 중에도 초안과 재생을 유지합니다.
- 개별 WAV 다운로드나 저장 포함 체크 없이 하단 **N개 선택 데이터셋 저장**으로 현재 체크한 항목 중 WAV가 준비된 음성과 정답만 저장합니다.
- 생성 과정·템플릿·숫자·배치 기록은 목록 하단에서 펼쳐봅니다.
- 작업 선택·새 작업·전체 삭제는 위쪽의 작은 도구 모음에, TTS 상태는 하단 한 줄에 표시합니다.
- 모바일은 작업을 불러온 뒤 설정을 접고 목록을 먼저 보여줍니다.

## 발화 직접 추가

발화 목록 위의 **직접 추가**를 누르면 발화문과 학습 정답을 직접 입력할 수 있습니다.
여러 문장을 넣을 때는 양쪽에 한 줄씩 작성하며 같은 줄끼리 연결합니다.
새 작업에서는 직접 입력 목록을 만들고, 기존 작업에서는 원래 항목을 유지한 채 추가합니다.
입력한 내용은 수동 검토한 것으로 저장되며 새 항목은 자동으로 선택됩니다.
기존과 같이 선택한 발화의 음성을 생성하고, WAV가 준비된 선택 항목만 데이터셋으로 저장합니다.
직접 입력은 LLM을 실행하지 않습니다. 기존 발화와 중복되는 항목은 기존 목록에서 수정해야 합니다.

## 1. 요구사항 입력

**이번 생성 프롬프트**에 주제·상황·원하는 정답 표기를 작성합니다.

> 일기예보와 냉장 보관에 관한 발화를 만들어줘. 영하와 소수점 온도를 포함하고,
> 정답은 -3.5℃, 발화는 영하 삼 점 오 도처럼 써줘.

온도·고객 상담·전문 용어 예시는 입력을 돕는 초안입니다. 주제나 단위를 코드에 등록할 필요는 없습니다.
숫자가 없는 일반 문장도 같은 생성 경로를 사용합니다.

**공통 생성 규칙**에는 자연스러운 숫자 읽기, 말투처럼 반복할 조건을 저장합니다.
공통 설정은 `data/asr_web/preferences.json`에 저장되고, 각 작업에는 실행 당시의 프롬프트와 공통 규칙이 기록됩니다.
나중에 공통 규칙을 바꿔도 이전 작업의 조건은 바뀌지 않습니다. 말투·주제는 이번 요청의 구체적인 조건을 우선합니다.
**숫자 읽기 규칙**의 단위·의미·읽기는 모델의 선택이나 프롬프트보다 우선하며 화면에서 추가·수정·삭제할 수 있습니다.
예를 들어 일 → 한자어, 명·시간 → 고유어, 개월 → 한자어로 설정하면
15일은 십오일, 15명은 열다섯 명, 15시간은 열다섯 시간, 15개월은 십오 개월로 생성됩니다.
의미별 규칙은 같은 단위의 ‘모든 의미’ 규칙보다 우선합니다.
‘분’은 시각·기간과 인원을, ‘번’은 횟수·순서·번호를 구분합니다. 이 단위들은 모델이 의미를 잘못 분류할 수 있어 문맥 확인 대상으로 표시합니다.
미등록 단위도 생성할 수 있으며 읽기를 검토한 뒤 공통 규칙으로 등록하면 다음 생성부터 재사용합니다.

만들 개수와 **저장 루트**를 입력한 뒤 **발화 생성**를 누릅니다.
배치 크기의 기본값은 **3개**이며 생성 설정에서 변경할 수 있습니다.
기본 저장 루트는 `/tmp/ai-dataset/`입니다.

## 2. 텍스트 검토

카드마다 TTS가 읽을 발화와 ASR 정답을 나란히 확인합니다.

- 목록의 체크는 음성 생성 대상을 선택합니다. 처음에는 선택하지 않은 상태로 시작합니다.
- **채택 항목 전체 선택**은 검증을 통과한 발화만 선택합니다.
- 목록 필터의 **채택됨**은 생성 체크 여부와 관계없이 확인이 필요 없는 채택 발화만 표시합니다. **선택됨**은 현재 체크한 발화만 표시합니다.
- 낯선 단위의 표기·발음 대응과 별도 발음은 **확인 필요**로 표시합니다. 행 아래에서 내용을 확인하고 사용을 허용한 뒤 생성 대상으로 체크합니다.
- 값이 서로 다르거나 형식을 확인하지 못한 결과는 자동으로 사용하지 않습니다.
- 발화·정답 입력창에서 바로 편집하고 저장할 수 있습니다.

**선택한 N개 음성 생성**을 누르면 체크한 문장만 음성으로 만듭니다.
음성이 이미 준비된 항목은 재사용하고, 미완료·실패 항목은 다시 시도할 수 있습니다.
텍스트만 필요하면 **텍스트 JSONL**로 검토 완료된 사용 문장을 내보냅니다.

## 3. 음성 검토·저장

생성된 WAV를 행의 재생 버튼과 파형으로 확인합니다.
**N개 선택 데이터셋 저장**을 누르면 목록에서 체크한 항목 중 준비된 유효 WAV와 정답만 저장됩니다.
WAV가 있어도 체크를 해제하면 저장 대상에서 제외됩니다. 선택한 항목의 WAV가 아직 없으면 저장하지 않습니다.
별도로 오디오·전사문을 매핑하는 버튼을 누를 필요는 없습니다.

마지막 저장 결과는 작업에 저장되어 새로고침 후에도 유지됩니다.
이전 화면의 개별 제외 기록 대신 현재 목록 체크를 기준으로 저장합니다.
발화를 바꾸면 음성을 다시 생성해야 합니다. 정답만 바꾸면 같은 WAV에 최신 정답을 연결합니다.

저장 루트를 바꿀 수 있으며 매번 새 `dataset-...` 폴더를 만듭니다.
이미 만든 WAV와 이전 데이터셋을 보존하고, 최종 선택 음성만 복사합니다.

```text
/tmp/ai-dataset/
  wav/<작업 ID>/<항목 ID>-<발화 버전>.wav
  dataset-<작업 ID>-<고유 ID>/
    audio/<항목 ID>.wav
    transcripts.jsonl
    dataset_info.json
    train.jsonl
    validation.jsonl
```

`/tmp`는 임시 저장 위치입니다. 장기 보관할 데이터는 영구 경로를 입력해 생성합니다.

## 생성 데이터 전체 삭제

위쪽 도구 모음의 **전체 삭제**를 누르면 모든 저장 작업과 연결된 WAV·매핑 결과의 개수와 저장 경로를 확인할 수 있습니다.
확인 창에서 **전체 삭제**를 누를 때 실제 파일을 삭제합니다. 취소하면 파일을 변경하지 않습니다.
모델·공통 설정과 앱 생성 파일로 식별되지 않는 추가 파일은 유지합니다.
생성 중에는 삭제할 수 없으며, 확인 후 대상이 바뀌면 다시 확인해야 합니다.

화면의 최근 100개 제한 밖의 작업도 포함합니다. 현재·이전 출력 루트와 여러 매핑 결과를 추적합니다.
별도로 복사한 파일, 기록이 없는 과거 저장 경로, 출처를 확인할 수 없는 폴더와 외부 심볼릭 링크는 삭제하지 않습니다.
일부 파일 삭제가 실패하면 남은 대상을 다시 확인하여 재시도할 수 있습니다.

## 공통 생성·검증 방식

LLM은 `parts`에 **일반 문장 → 변환 표현 → 일반 문장**을 읽는 순서대로 작성합니다.
일반 문장은 `{"text":"내용"}`, 숫자는 기본적으로 `{"value":"15","unit":"명"}`처럼 값·단위만 가진 객체입니다.
앱이 공통 속성을 보완하며, 기호·외국어 단위의 발음이나 특별한 읽기가 필요할 때만 속성을 추가합니다.
발음이 다른 약어는 `{"value":"API","reading":"custom","spoken":"에이피아이"}`처럼 작성합니다.
앱이 이 순서를 한 번 연결해 같은 값의 발화와 정답을 만듭니다.
모델이 별도의 문장 틀과 표현 배열의 번호를 맞추지 않으므로, 여러 날짜나 복합 표현을 추가해도 연결 분기를 만들지 않습니다.
숫자가 없는 문장은 일반 문장 객체 하나만 사용합니다.
금리·이율·기술 용어 등 주제를 바꿀 때는 생성 프롬프트와 공통 설정을 바꿉니다.
`%·%p·bp·kPa` 같은 단위나 새 약어를 도메인 목록·소스·출력 스키마에 등록하지 않습니다.
그대로 읽는 용어는 일반 문장으로, 발음이 다른 약어는 별도 표기·발음 표현으로 전달합니다.
새 프롬프트 작업은 먼저 사용자 주제 안에서 상황·발화 목적·문장 전개를 계획합니다.
최대 16개의 계획에 목표 개수를 고르게 배분하며, 아직 시도하지 않은 상황부터 순환합니다.
계획을 적용하는 로컬 작업은 한 번에 상황 하나·문장 하나를 생성하여 작은 모델이 여러 계획을 뒤섞지 않게 합니다.
세부 설정의 배치 크기는 계획 없는 기존 생성 경로에 적용됩니다.
계획과 시도 횟수는 작업에 저장되고 계획 추론은 요청 기록의 `phase: planning`으로 구분됩니다.
기존 문장을 성공 예시로 반복해서 제시하지 않고, 값을 가린 형식을 `used_patterns`로 전달해 재사용을 피합니다.
숫자·전화번호·고유명사·인사말만 바뀐 같은 형식과 긴 문장의 높은 유사도 반복은
`structure_duplicate`로 자동 제외하고 목표 개수에 포함하지 않습니다.
숫자 값은 단위 없는 숫자 문자열로 출력하도록 스키마를 제한하며,
복합 표현은 필요한 값과 일반 문장 조각을 순서대로 이어 씁니다. 숫자 외 별도 발음은 빈 발음을 출력할 수 없습니다.
등록된 한글 단위의 발음이 비어 있으면 해당 단위 자체로 보완하며, 기호·낯선 단위의 발음은 추측하지 않습니다.
일반 문장에 남은 숫자, 변환 번호, 태그 구분자 등은 생성 형식 오류로 처리합니다.
이전 `template+expressions` 자료는 호환 입력으로 지원합니다.
연결이 명확한 반복 묶음은 단위·읽기·역할의 구조를 비교해 복구하고 검토 표시를 남깁니다.
본문에 쓰이지 않은 값은 문장에 삽입하지 않으며, 값이 부족하거나 연결이 모호하면 추측하지 않습니다.
복구 가능한 이전 실패 결과는 같은 ID의 검토 대상으로 다시 표시하되 저장 파일은 자동 수정하지 않습니다.
수동 제외와 중복 제외 결정은 유지하며, 복구 결과도 사람이 확인하기 전에는 WAV 대상으로 사용하지 않습니다.
복구가 불가능한 경우에는 실제 실패 사유와 생성 원문을 펼쳐 확인할 수 있습니다.
단위 없는 숫자는 문맥 확인 대상으로 표시합니다. 수치 대응만으로 문장 의미의 정확성을 보장하지 않습니다.
같은 설치 위치에 `llama-cli`가 있으면 구조화 응답·생각 과정 제어를 위해 우선 사용합니다.
CLI의 안내·프롬프트 표시는 제외하고 검증한 JSON 응답만 처리합니다.
‘검증 통과 선택’에서도 반복 제외 항목은 선택하지 않으며, 필요한 변형은 사람이 개별 선택할 수 있습니다.
5개 배치 연속으로 새 결과를 채택하지 못하면 기존 결과를 보존하고 일부 완료로 중단합니다.
새 주제를 코드에 등록할 필요는 없으며, 의미상 다른 상황을 모델이 정확하게 생성했는지는 검토가 필요합니다.
단위는 작업에서 표기와 발음을 선언합니다. 예를 들어 `℃ → 도`, `kPa → 킬로파스칼`처럼
코드에 없는 단위도 같은 경로로 처리합니다.

한자어·고유어 수 관형사·자릿수·연월일·시각·전화번호 등의 공통 읽기를 재사용합니다.
금액의 천·백·십 앞에서 불필요한 일을 생략하고, 인원·수량은 열 명·스무 명처럼 읽을 수 있습니다.
영하·소수점·선행 0·단위 값의 대응을 검사하며, 같은 단위를 두 번 붙이지 않습니다.
새 프롬프트 결과는 실행 당시의 읽기 정책으로 검토·저장 시 다시 검사하므로
숫자 값이 같아도 ‘열다섯 일’이나 ‘십오 명’처럼 규칙과 다른 읽기는 채택할 수 없습니다.
이전 프롬프트 결과에 읽기 정책이 없으면 기본 단위 규칙으로 검사하고 불일치 결과를 검토 대상으로 표시하며, 원문 파일은 자동 수정하지 않습니다.
단위 발음에 금액·수량을 함께 넣은 응답은 거부합니다. 예를 들어 55,000원의 단위 발음은
‘원’이며 ‘오만 오천 원’이 아닙니다. 저장된 표기·발음 대응도 별도로 검사하여 같은 오류가 검증을 우회하지 못하게 합니다.
확인이 끝나지 않은 결과는 다음 생성의 채택 예시로 사용하지 않습니다.

자유로운 약어·전문 용어의 발음과 새로운 표기 대응은 사람이 검토해 확정합니다.
자료 구조를 모든 주제에 공통으로 사용하더라도 전문 내용의 사실성이나 발음까지 자동으로 보장하지는 않습니다.
기존 숫자 모드와 일반 발화 데이터는 호환 목적으로 읽을 수 있으며, 저장된 원문을 자동으로 고치지 않습니다.

## Qwen ASR 연결

WAV는 16kHz 모노 PCM16이며 60초 이내의 유효한 파일만 저장합니다.
`transcripts.jsonl`에는 선택한 음성과 접두어 없는 정답을 기록합니다.

```json
{"id":"항목 ID","audio":"audio/항목 ID.wav","text":"기온은 -3.5℃입니다.","spoken_text":"기온은 영하 삼점오 도입니다.","sampling_rate":16000,"num_frames":16000,"duration_seconds":1.0}
```

서로 다른 정답이 2개 이상이면 기존 `qwen3-asr-finetuning` 데이터 로더가 읽는
`train.jsonl`·`validation.jsonl`도 생성합니다.
같은 정답 그룹이 양쪽에 섞이지 않도록 그룹의 약 10%(최소 1그룹)를 검증용으로 고정합니다.
정답이 1개뿐이면 WAV와 전체 전사 매핑만 생성합니다. 실제 학습은 별도 학습 프로젝트에서 실행합니다.

## 로컬 TTS 설정

기본 실행은 `~/Desktop/personal/dev/ai-models/MOSS-TTS-8B-BF16` 본체와
`MOSS-Audio-Tokenizer-BF16` 코덱, 기존 `.voxtral-mlx-tools/bin/python`을 사용합니다.
추론 중 네트워크 다운로드는 차단하며 가중치·텍스트 토크나이저·코덱이 모두 있어야 시작합니다.
텍스트 음성 합성에서는 참조 음성 인코더를 제외하고 코덱의 디코더·양자화 코드 복원부만 로딩합니다.
본체와 사용되는 코덱 가중치의 BF16 정밀도는 유지합니다.
음성 샘플링 온도(`audio_temperature`)는 기본 **1.5**를 사용합니다. 텍스트 샘플링 설정은 별도로 유지합니다.
온도는 WAV 캐시 식별자에 포함되므로 이전 설정으로 생성한 WAV는 새 설정의 결과로 재사용하지 않습니다.
8bit 모델로 자동 전환하지 않습니다. 자식 프로세스의 MLX 메모리 예산은 기본 20GiB이며
`--tts-memory-limit-gb`로 변경할 수 있습니다. MLX의 메모리 예산은 강제 상한이 아닌 할당 지침이며
실제 전체 프로세스 사용량과 다릅니다. GPU 메모리 상주 범위는 지정 예산과 장비 권장치 중 작은 값으로 설정합니다.
운영체제의 sysctl 설정은 변경하지 않습니다.

기존 Magpie를 직접 선택하려면 다음 옵션을 사용합니다.

```bash
python3 -m asr_corpus.web \
  --tts-backend magpie \
  --tts-model-dir ~/Desktop/personal/dev/ai-models/magpie-tts-multilingual-v2607 \
  --tts-executable ~/.local/bin/nemo-speech \
  --tts-device metal \
  --tts-speaker 0
```

화자는 `0`~`4`, CPU 실행은 `--tts-device cpu`로 지정합니다.
모델 디렉터리에 F16 GGUF, NanoCodec 디코더 GGUF, 추출된 `tokenizer/`가 필요합니다.
현재 환경은 준비되어 있으며, 음성 생성에 추가 모델 다운로드를 사용하지 않습니다.
실행 도구 재설치는 [NVIDIA 공식 안내](https://github.com/NVIDIA/NeMo-Speech.cpp/blob/main/docs/install.md)를 따릅니다.
